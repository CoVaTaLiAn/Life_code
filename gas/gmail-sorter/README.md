# Gmail 自動振り分け（GAS）

1時間ごとに未読メールを振り分け、毎朝7時に要約メールを自分宛てに送る。
振り分けは **既読／残す／迷惑メール** の3つだけ。決まらないものはあなたに聞く。

| 振り分け | 処理 | ラベル |
|---|---|---|
| 既読 | ただの通知・宣伝。既読にして受信箱に残す | 既読 |
| 残す | 読むべきもの。未読のまま受信箱に残す | 残す |
| 迷惑メール | 明らかなスパム。Gmail の迷惑メールへ（30日で自動削除） | なし |
| 要判断 | 決まらないもの。未読のまま、シート「判断待ち」に載せて要約で聞く | 要判断 |

ほかに、Contract One など `trashSenders` の送信元は既読にしてゴミ箱へ移す。

トークン（費用）を使うのは迷ったメールだけになるよう、次の順で判定する。

```
新着メール
  │
  ├─ 1. ルール（GAS・無料）……… 送信元・キーワード・あなたが過去に決めた送信元
  │
  ├─ 2. 確率（ルールに当たらないものだけ）
  │      Jev（TYPESAFE_API_KEY があるとき）か、過去の判定から学ぶ簡易計算（無料）で
  │      「スパム確率」「既読でよい確率」を出す。95%以上ならそのまま処理
  │
  ├─ 3. Claude（Claude Code で頼んだときだけ）
  │      シート「判断待ち」の行（差出人・件名・冒頭100字・確率）だけを見て提案を書く
  │
  └─ 4. あなたが「既読」か「残す」（か「迷惑メール」）を決める
         → GAS が1時間以内に処理し、その送信元を覚える（次からは 1 で自動）
```

判定結果は、ルール・Jev・簡易計算・あなたのどれで決まったかも含めて、すべてスプレッドシート「Gmail振り分けログ」に残る。

## 迷ったメールの片付け方

1. Claude Code（このリポジトリ）で「**Gmailの判断待ちを見て**」と頼む
   → Claude がシート「判断待ち」に提案を書き、一覧を見せる（手順：`.claude/skills/gmail-triage/SKILL.md`）
2. 「全部OK」「3は残す」のように答える → Claude が「あなたの判断」列に書く
3. 1時間以内に GAS が処理し、同じ送信元は次から自動でそうなる

Claude を使わずに決めてもよい：

- シート「判断待ち」の「あなたの判断」列（選択式：既読／残す／迷惑メール）で選ぶ
- Gmail でメールを開き「既読」か「残す」のラベルを付ける（「要判断」は外さなくてよい）

覚えた送信元は、スクリプト プロパティの `LEARNED` に入っている。消せば忘れる。

## ルール

`Code.gs` 冒頭の `CONFIG` を書き換えれば変えられる。上から順に当てはめる。

1. あなたが過去に決めた送信元
2. 迷惑メール：件名の `spamKeywords`（「高額当選」など）、送信元の `spamSenders`（`.xyz` などの怪しいドメイン）
3. 残す：件名の `keepKeywords`（Security alert・ログインなど）
4. 既読：送信元の `readSenders`（Amazon・LinkedIn・GitHub など）、件名の `readKeywords`（規約改定・メンテナンスなど）

間違って迷惑メールに入ったら、Gmail で「迷惑メールではない」を押し、シートか Gmail のラベルで正しい振り分けを教える。

以前の版のラベル（転職/注目・転職/その他・広告・通知・要確認・要返信）は使わなくなった。付いているメールはそのまま。
以前に覚えた送信元は、広告・通知・転職/その他 → 既読、転職/注目・要確認・要返信 → 残す として引き継ぐ。

## 確率の出し方

- **Jev**（TypeSafe AI の判断専用モデル）：スクリプト プロパティに `TYPESAFE_API_KEY` を登録したときだけ使う。1回の実行で最大20件
  - 呼び出し先・モデル名は `CONFIG.jev`。質問は Noul（はい である確率 0〜1）を2つ：「明らかなスパムか」「読まずに既読にしてよいか」
    （公式資料：https://docs.typesafe.ai/primitives/noul ）
  - 動いているかは毎朝の要約メールの「Jev：○件判定」で分かる。エラーのときは自動で簡易計算に切り替わり、要約にエラー内容が載る
  - すぐ確かめたいときだけ、GAS エディタで `testJev` を実行する（任意）
- **簡易計算**（キーなしでも動く・無料）：判定ログのうち「ルール」と「あなた」が決めた行から、送信元と件名の言葉で学ぶ
  - 各グループの学習例が10件（`CONFIG.prob.minExamples`）たまるまでは自動処理せず、確率を参考に出すだけ
  - 迷惑メールへの自動移動は、過去にスパムだった送信ドメインに限る（確率が極端に出やすいため）

## 設置手順

1. https://script.google.com を開き「新しいプロジェクト」
2. 最初からある `コード.gs` の中身を消し、`Code.gs` の内容を貼り付けて保存
   （GitHub からの自動反映を設定済みなら不要。手順：`../SETUP_PC.md`）
3. Jev を使う場合：左メニューの「プロジェクトの設定」→「スクリプト プロパティ」→「プロパティを追加」
   - プロパティ：`TYPESAFE_API_KEY`
   - 値：TypeSafe AI で発行した API キー
4. 上部の関数選択で `setup` を選び「実行」
5. 権限の確認画面で「詳細」→「（安全ではないページ）に移動」→「許可」
   （自分で作ったスクリプトなので出る警告。Gmail・スプレッドシート・外部API呼び出しの権限を求める）

止めるときは左メニューの「トリガー」から2つとも削除する（片方だけ消すと、残った `sortInbox` が作り直す）。

コードを更新したあと `setup` を実行し直す必要はない（ラベルとトリガーは足りなければ自動で作られる）。

## サブの Gmail でも使う

Gmail ごとに GAS を1つずつ置く（同じコード）。判断はスプレッドシート経由なので、Claude の Gmail 接続はメインのアカウントだけでよい。

1. **サブのアカウント**でログインし、上の「設置手順」1〜2 で GAS を作る
2. スクリプト プロパティに `SHARE_WITH` = Claude をつないだメインのアカウントのアドレスを登録する
   （ログのシートがそのアカウントに編集者として共有され、Claude が「判断待ち」を読み書きできる）
3. `setup` を実行する。シート名は「Gmail振り分けログ（サブのアドレス）」になる
4. 自動反映する場合：GAS の「共有」でメインのアカウントを編集者に追加し、
   GitHub の Variables に `GAS_SCRIPT_ID_SUB` = サブの GAS のスクリプト ID を登録する（手順：`../SETUP_PC.md`）

サブのアカウントでは、Claude が Gmail のラベルを直接付けられない。決めるのはシートの「あなたの判断」列（Claude に頼めば Claude が書く）か、サブの Gmail で自分で「既読」「残す」のラベルを付ける。

## 費用の目安

- ルール・簡易計算：無料
- Jev：ルールに当たらないメールだけ（今の受信箱なら1日数件）。料金は TypeSafe AI の料金表を確認
- Claude：Claude Code で頼んだときだけ。シートの短い行だけを読むので、1回あたりのトークンは少ない

以前の Claude API による自動判定（`ANTHROPIC_API_KEY`）は、この仕組みに置き換えたため使わない。
