# データプロファイリング（調べて報告するだけ。変更しない）

前処理は役割ごとに3つの処理に分かれている。**この処理はプロファイリングだけ**を行う。

| 処理 | 役割 | スキル |
|---|---|---|
| プロファイリング | 中身を調べる。エンコーディングを勧める | これ |
| クレンジング | 汚れを段階的に直す | `data-cleansing` |
| エンコーディング | 計画に従って数値にする | `data-encoding` |

流れ: **プロファイリング（生データ）→ クレンジング → プロファイリング（クレンジング後）→ エンコーディング**。
出力先は `D=analysis/<YYYY-MM-DD>_<名前>`。データは `$D/data/` に置く（CSV は git に入らない）。

## 実行
```bash
S=.claude/skills/data-profiling/scripts/profile_data.py
python3 $S --input $D/data/raw.csv --out $D/01_profile_raw [--target <目的変数>] [--title "<名前>"]
# クレンジング後にもう一度（隣の cleaned.schema.json から列の種類を読む）
python3 $S --input $D/02_cleanse/cleaned.csv --out $D/03_profile_cleaned [--target <目的変数>]
```
必要なのは pandas と numpy だけ。文字コード（UTF-8 / Shift_JIS など）と区切り文字は自動で判定する。

## 出力（`--out` の中）
| ファイル | 内容 |
|---|---|
| `report.md` / `report.html` | レポート。全体、列の一覧、数値列の統計値、カテゴリ列の中身、日時・文章・ID、品質の気づき、相関の強い組、おすすめのエンコーディング |
| `encoding_plan.json` | 列ごとのエンコーディング計画（方法・理由・代わりの案）。エンコーディングに渡す |
| `profile.json` / `column_profile.csv` | 列ごとの数値一式 |

## レポートの読み方と、次にすること
1. `report.md` を読む。種類の判定がおかしい列（数値のはずがカテゴリなど）を探す → クレンジングの段階3で `--kind` を指定する
2. 「品質の気づき」は**対応するクレンジングの段階**ごとに並んでいる。ここに挙がった件を持ってクレンジングに進む
3. おすすめのエンコーディングは目安。課題の意味で変えたい列は `encoding_plan.json` の `method` を書き換える（生データ時点の計画は使わない。クレンジング後に作り直したものを使う）

エンコーディングの勧め方（スクリプトの判断基準）:

| 列の性質 | 方法 |
|---|---|
| ID、値が1種類、欠損 95% 以上 | `drop` |
| 値が2種類 | `binary` |
| 数値（偏りなし） | `passthrough`（線形モデルなら `standard`） |
| 数値（0 以上で歪度 > 1） | `log1p` |
| カテゴリ 10 種類以下 | `onehot`（順序が読み取れれば `ordinal`） |
| カテゴリ 11 種類以上 | 目的変数があれば `target`、なければ `frequency` |
| 日時 | `datetime`（年・月・曜日＋周期） |
| 文章 | `text_stats`（文字数・単語数） |

## 渡す
- `report.html` を SendUserFile で送る
- 返答には、行数×列数、列の種類の内訳、品質の気づきの上位、エンコーディングで判断が要る列を書く
- 見本: `analysis/example_dataprep_sample/01_profile_raw/report.md`
