# PubMed 網羅調査

スクリプト: `.claude/skills/pubmed-survey/scripts/pubmed_survey.py`（Python 3 標準ライブラリのみ）
以下 `S=.claude/skills/pubmed-survey/scripts/pubmed_survey.py`、`D=research/<YYYY-MM-DD>_<テーマ英語スラッグ>`。

## 前提
- 接続先 `eutils.ncbi.nlm.nih.gov`（クラウド環境ではネットワーク許可が必要）
- 環境変数 `NCBI_API_KEY`（任意、3→10件/秒）と `NCBI_EMAIL` があれば自動で使う
- 確認: `curl -s -o /dev/null -w "%{http_code}" "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/esearch.fcgi?db=pubmed&term=test"` が 200

## 手順

### 0. 目的の確認
ユーザーの「調べたいこと / 実現したいこと」を1〜2文で言い直し、`$D` を作る。
検体・手法・対象など **ユーザーが列挙した軸はすべて個別に検索する**。目的が曖昧なときだけ1回質問する。

### 1. 検索式を網羅的に作る → `$D/queries.txt`
目的を **概念ブロック**（対象疾患・手法/分子・検体/介入・アウトカム）に分け、各ブロックの同義語・略語・英米綴り・MeSH を洗い出す。

- 構成（目安 25〜40本）:
  1. 広い: 疾患だけ、疾患×手法、疾患×手法×診断、レビュー版 → ヒット数の記録用
  2. 軸ごと: ユーザーが挙げた各軸（例: 検体ごと）について、広い版と狭い版（＋診断性能、＋検証、＋周期/病期など）
  3. 比較用: 隣接する代替手段（例: 他の検体、他のバイオマーカー）
- 各ブロックは `("Term"[MeSH Terms] OR term[tiab] OR "phrase"[tiab])`。ワイルドカードは `diagnos*[tiab]` の形
- 日本語の概念は英語にする。略語は展開形も併記する
- 1行1検索式。`#` の行はコメント（ブロック名のメモ）

### 2. 検索 → 調整（最大2周）
```bash
python3 $S search --queries $D/queries.txt --out $D --max 50
```
- 全検索式のヒット数を `hits.json` に記録し、50件以下の検索式だけ論文とアブストを `papers.json` に取る（重複は自動で除外）
- **調整:** 中心となる検索式が50件を超えたら、年代で分ける（`AND 2018:2020[dp]`）か、条件ブロックを AND で足した版を `queries.txt` に **追記** して再実行する（上書きで OK、既存の番号は変わらない）。0件ばかりなら同義語や MeSH を足す

### 3. 採点（全件）
基準（目的に合わせて具体例を書き換える）:

| 点 | 基準 |
|---|---|
| 5 | 目的とほぼ同じ（同じ対象・手法・検体で、性能などの結果がある） |
| 4 | 主要な要素の大半が一致／その領域の系統的レビュー・メタ解析／別手法で同じ目的 |
| 3 | 一部一致。方法・データ・知見が参考になる |
| 2 | 背景知識 |
| 1 | 関連が薄い |

**60本以下:** 自分で全部読んで `$D/scores.json` を書く。
**60本超:** 分割して並列に採点する。
```bash
python3 $S chunk --out $D --n 4     # 約100本ずつ → $D/chunks/chunk{k}.txt
```
Agent ツール（general-purpose）を **同時に** 起動する。プロンプトの雛形:
> `$D/chunks/chunk{k}.txt` を全部読み（大きければ offset/limit で分けて）、全論文を採点。目的: <目的>。基準: <上表を具体化したもの>。
> Write で `$D/chunks/scores{k}.json` に `[{"pmid":"…","score":5,"reason":"日本語1文。検体・手法・n数・性能(AUC/感度/特異度)・独立検証の有無など"}]` を保存。アブストがなければタイトルで採点し「アブストなし」と書く。
> 返答: 採点数、4点以上の論文を「PMID | 点 | 検体/対象 | 主要マーカー | n | 性能 | 独立検証 | 限界」の形で全部、さらにハードルに関わる事実（再現失敗・小規模・交絡・標準化・コスト・規制・商用品など）を PMID 付きで。アブストの記述のみを根拠に。

```bash
python3 $S merge --out $D           # missing=[] extra=[] を確認。漏れがあれば追加で採点
```

### 4. まとめ → `$D/summary.md`
サブエージェントの報告と主要論文のアブスト（`papers.json`）を見て書く。**引用する PMID は必ず papers.json で中身を確認する。** 推測は推測と書く。

```markdown
**目的:** …
## 結論（3行）
## 似たことをやっている研究はあるか
**判定: あり / 部分的にあり / 見当たらない**
（軸ごとの表: 軸 | ヒット数 | 到達段階 | 代表 PMID。最も近い研究と、目的との違い。メタ解析・レビューの結論）
## 実現に向けたハードル
| ハードル | 内容 | 根拠 (PMID) | 対策の方向性 |
（再現性、規模・過学習、対照群の選び方、交絡、検体の品質・標準化、コスト・規制・利益相反 など）
## 空白領域・差別化ポイント
## 調査の限界
```

### 5. レポート出力
```bash
python3 $S render --out $D          # report.md（全件・アブスト付き）, top.md（4点以上の一覧だけの軽量版）
```
`unscored` が 0 でなければ 3 に戻る。
`$D` を git に commit・push する（`chunks/` も含めてよい）。

### 6. ユーザーへの報告
結論（似た研究の有無、ハードルの要点、差別化の方向）を短く伝え、`report.md` のパスを示す。

### 7.（頼まれたら）メール送付
```bash
python3 $S email --out $D --min-score 5    # $D/email.html: まとめ＋5点の論文一覧（リンク付き）
```
`email.html` の中身を Gmail の `send_message` の `htmlBody` に入れて送る。report.md は大きいので添付しない。全文の置き場所（リポジトリのパス）を本文の最後に書く。
件名の例: `【論文調査】<テーマ>`
