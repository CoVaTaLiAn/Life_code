# PubMed 網羅調査

スクリプト: `.claude/skills/pubmed-survey/scripts/pubmed_survey.py`（Python 3 標準ライブラリのみ）

## 手順

### 0. 目的の確認
ユーザーの「調べたいこと / 実現したいこと」を1〜3文で言い直し、出力フォルダを決める
（例 `research/2026-10-29_テーマ名/`）。目的が曖昧なら1回だけ質問する。

### 1. 検索クエリを網羅的に作る → `queries.txt`
目的を **概念ブロック**（対象・介入/手法・アウトカム・対象集団 など）に分解し、
各ブロックの同義語・略語・英米綴り・MeSH 用語を洗い出してからクエリを組む。

- 広いクエリ（1〜2ブロック）から狭いクエリ（3〜4ブロックの AND）まで段階的に並べる
- 各ブロックは `("term A"[tiab] OR "term B"[tiab] OR "Term"[MeSH Terms])` の形
- 日本語の概念は必ず英語に。略語は展開形も併記
- 目安 15〜40 クエリ。広すぎるもの（数千件）も **ヒット数の記録のために残す**
- 必要に応じてレビュー絞り込み `AND review[pt]`、年 `AND 2015:2026[dp]` の版も追加
- 1行1クエリ、`#` 行はコメント（ブロック名などのメモに使う）

### 2. 検索を実行
```bash
python3 .claude/skills/pubmed-survey/scripts/pubmed_survey.py search \
  --queries <out>/queries.txt --out <out> --max 50 --email "$NCBI_EMAIL"
```
- 全クエリのヒット数を `hits.json` に記録
- ヒット数 ≤ 50 のクエリだけ論文情報＋アブストを取得し `papers.json` へ
- 別クエリで既に出た論文は再掲しない（`found_by` は最初に見つかったクエリ番号）
- `NCBI_API_KEY` 環境変数があれば自動で使う（速度 3→10 件/秒）

**ヒット数を見て調整（最大2周）:**
- 全部 50 件超で論文がほぼ取れない → ブロックを AND で追加した狭いクエリを足す
- 0 件ばかり → 用語が狭すぎ。同義語や MeSH を足す
- 調整したら queries.txt に追記して search を再実行（上書きで OK）

### 3. 優先順位付け → `scores.json`
`papers.json` のアブストを **全件** 読み、目的への合致度を採点する。

| 点 | 基準 |
|---|---|
| 5 | 目的とほぼ同じことをしている（直接の先行研究） |
| 4 | 主要な要素の大半が一致（手法 or 対象が同じ） |
| 3 | 一部の要素が一致し、手法・データ・知見が参考になる |
| 2 | 背景知識として有用 |
| 1 | 関連が薄い |

形式: `[{"pmid": "123", "score": 5, "reason": "日本語で1文、何が一致/不一致か"}, ...]`
件数が多い（100件超）ときは Agent ツールで分割して並列採点してよい。

### 4. まとめ → `summary.md`
アブストに書かれた事実を根拠にし、必ず PMID を引用する（推測は推測と明記）。

```markdown
## 結論（3行）
## 似たことをやっている研究はあるか
- 判定: あり / 部分的にあり / 見当たらない
- 最も近い研究 (PMID) と、目的との違い
- 研究の量・時期の傾向（ヒット数の推移、レビューの有無）
## 実現に向けたハードル
| ハードル | 内容 | 根拠 (PMID) | 対策の方向性 |
（技術・データ/サンプル・倫理/規制・コスト・評価方法 などの観点で）
## 空白領域・差別化ポイント
## 調査の限界
（PubMed のみ、アブストのみで判断、50件超のクエリは未取得 など）
```

### 5. レポート出力
```bash
python3 .claude/skills/pubmed-survey/scripts/pubmed_survey.py render --out <out>
```
`report.md` = summary.md + ヒット数表 + 優先度順の一覧 + 各論文の詳細（アブスト付）。
`unscored` が 0 でなければ採点漏れなので 3 に戻る。

最後にユーザーへは「結論3行」とレポートのパスだけ短く伝える。

## 注意
- 接続先: `eutils.ncbi.nlm.nih.gov`。クラウド環境ではネットワーク許可が必要
- アブストは英語のまま保存。理由・まとめは日本語
- アブストがない論文はタイトルで採点し、reason に「アブストなし」と書く
