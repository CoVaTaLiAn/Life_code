# 書類の型

## 計画書（plan.md）

```markdown
# <案件名>

- 受付日: YYYY-MM-DD
- 目的:
- 成果物:
- 制約:
- 合格基準:
- 置いた前提: （オーナーに確認していないこと）

## タスク

| ID | フェーズ | 部署（エージェント） | 内容 | 入力 | 出力 | 依存 |
|---|---|---|---|---|---|---|
| T1 | 1 | web-researcher | | 依頼文 | T1_research.md | - |
| T2 | 1 | paper-researcher | | 依頼文 | research/.../report.md | - |
| T3 | 2 | writer | | T1, T2 の出力 | T3_draft.md | T1, T2 |
| R3 | 3 | reviewer | T3 の検収 | T3_draft.md | review_T3.md | T3 |

## 決裁が必要になりそうなこと
- （例: 下書きしたメールの送信）
```

## 発注書（Agent に渡すプロンプト）

```text
【案件】<案件名>：<目的を1〜2行>
【あなたの担当】<タスクID>：<このタスクでやること>

【入力】（先に読む）
- /home/user/Life_code/company/<案件>/plan.md
- <前フェーズの成果物の絶対パス>

【出力】
- /home/user/Life_code/company/<案件>/<ID>_<種類>.md に書き出す

【合格基準】
- <箇条書き>

【やってはいけないこと】
- 送信・登録・公開・共有・コミット・push（下書きまで）
- 根拠のない断定（推測は「推測」と書く）

【返信】要約10行以内＋出力ファイルのパスだけを返す。
```

## 報告書（report.md）

```markdown
# <案件名> 報告

## 結論（3行以内）

## 成果物
| 内容 | 担当 | パス | 検収 |
|---|---|---|---|

## 未解決・要確認

## 決裁をお願いしたいこと
- [ ] （例: T4 の返信下書きを送信してよいか）

## 次の一手
```
